# LINE任務清單簡化

群組預設「簡潔任務清單」：同日期、同車隊群組的所選車趟合併成一份清單，依出車時間與任務碼排序。每趟只顯示唯一可操作的路線／任務碼、出車時間、取貨點與店數；不包含逐站地址、重複狀態與一長串指令。店數為各趟加總，不當作全日不重複門店數。

固定路線使用既有「接取 路線編號 司機ID」流程，仍須LINE綁定、本人驗證與名額檢查；完整站點依既有私訊本人路線功能取得。不是自動向所有群組成員公開。若同一路線同車隊同日多趟，清單顯示唯一任務碼，避免路線碼歧義。舊版非接取車趟保留逐趟報到指令。

發布視窗直接展開實際訊息，另外可選「完整逐站明細」。完整模式仍保留原有逐趟發布，使用者確認前不發送。零選取、未綁定、準備中、資料變更與錯誤均有明確提示，不再默默停用或關閉視窗。確認排隊後顯示趟數與群組清單份數；排隊不是送達，仍應核對工作台紀錄。

## API與儲存

新增POST /api/store-delivery/trips/summary-preview，items包含tripId、version、groupId，登入admin／dispatcher才可用。只預覽，不建立通知工作。

POST /api/store-delivery/trips/batch-notify增加details=summary；原full與舊模式保留。驗證1～50趟、同日同車隊同群組、版本、啟用／Bot在場及模擬限制後，在既有交易內建立一個deliverySummary工作，回傳queued（趟）、duplicate（趟）、messages（合併清單工作數）。沒有migration或新Secrets。

佇列儲存已預覽文字及車趟版本；工作者發送前重新驗證。相同車趟版本已在簡表工作中時，即使換選取順序或只重選部分，也不重排。LINE重試沿用工作UUID。任務／群組變更則失敗，不悄悄發送新資料；於工作台依既有流程處理。簡表與完整明細為不同發布模式，不自動重發此前已發布的任務。

長清單仍可能由既有LINE文字分段器拆分；一份工作不保證只佔一則計費訊息，未承諾免用量。未變更接取、報到、退趟或Google同步規則。

## 驗證範圍

整合測試包含摘要不洩漏地址、權限與版本／群組驗證、兩趟一份清單、重複／部分重疊選取去重、實際工作者模擬LINE API與穩定retry key、版本改變阻擋；介面測試包含預設簡表、完整模式切換、零選取提示、確認才排隊。全部使用獨立本機測試資料庫與模擬LINE，不向真實車隊發送。
