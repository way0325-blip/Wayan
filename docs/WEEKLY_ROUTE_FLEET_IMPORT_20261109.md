## 操作與更新邏輯

蝦皮店到店→路線範本與每日任務匯入→週期路線、碼頭與車行檔案匯入。

1. 先選路線車行對照，填原分頁名「路線&車行」，選CSV／TSV或準備JSON，預覽、核對並儲存來源版本。
2. 再匯入週期路線，填完整分頁名稱及明確起始年份。解析名稱的兩個月／日，不固定加7或8天；2rd／1nd依使用者確認僅為標記。跨年可跨到下一年，範圍最長32天。若檔案有日期欄，額外核對在週期內，只顯示適用當日的路線。
3. 來源車行與LINE車隊名冊分開。從下拉選單設定FXG／富詠等來源車行對應到哪個既有啟用車隊；不猜別名、不建立或綁定LINE群組。
4. 選擇作業日，平台自動取涵蓋該日期的最新已匯入版本。新週期11/17～11/24匯入後，日期17日起就選新版本；16日仍查舊版。超出所有週期不沿用舊表。
5. 勾選／全選可建立路線，人工核對後建立本日待派車趟。不自動展開整個期間、不發送LINE。未對應名冊的車行保留原名，出現在主清單「來源車行：名稱（待對應）」；可再按既有流程指派。

只有檔案上傳與人工核對是手動；欄位辨識、碼頭對照、路線車行合併、當日週期選取與去重自動處理。來源未授權前，不能宣稱每週五自動下載或全天候雲端同步。

來源版本與車行對應有資料庫即時事件；其他人更新時，未編輯的展開清單會刷新。正在預覽或已選路線則提示重新核對，不清掉輸入或悄悄改派。當前實際檔案交叉核對：21條在車行對照內，7條可建趟；預設只看對照內路線，可切換全部156條。整份來源中135條缺少有效車行對照、106條碼頭待核對（兩者可能重疊），不代表可自動安排156趟。

## 碼頭與安全限制

C／B＝長榮倉（既有CHANGRONG），T＝水源倉（SHUIYUAN），D＝國際倉（新增GUOJI及獨立國際倉主檔，地址空白）。支援字母加數字如C03、B15、T-2、D32；純數字301、311、504及未知字首待核對。週期碼頭優先，空白才採路線車行對照值。

來源實際有W路線配C／D碼頭，因此此週期匯入不套用舊版「W一定楊梅」取貨限制；路線箱型仍保留，取貨倉依使用者核對的碼頭規則。原有手動建趟及舊來源範本的箱型檢查保留；本次沒有重新分類既有任務。未知／缺漏資料不補猜。國際倉未假設地址、行政區或可用停車資源。

相同來源版本重送不重複儲存；較舊版本重送不回復最新版。相同日路線已有車趟時，不重複建立；來源版本、碼頭、車隊或站序有變更則要求使用原車趟調整，不覆蓋已派遣、接取、報到或歷史。取消過的車趟也不悄悄重建。各站訂單以趟計價，quantity為NULL。

後端有admin／dispatcher登入授權；匯入、別名設定與建趟限admin。建趟採交易、共用派遣鎖、名冊有效性及每日車隊容量檢查；失敗全批回滾，成功保留稽核。沒有LINE自動發布、沒有扣款或計罰。
