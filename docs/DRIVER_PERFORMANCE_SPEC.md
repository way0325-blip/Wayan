# Wayan 自有司機績效評估與違規累積管理規格

狀態：需求規格 v1.0；尚未實作程式或部署。
分支：feature/shopee-exception-penalty

## 1. 目的與範圍
本模組管理公司自有司機，不與合作車隊績效/罰款混為一談。以客觀事件紀錄為基礎，提供月、季及年度評估，支援主管面談與改善追蹤。評分規則、門檻及權重均由管理端設定，正式啟用前由公司確認並公告。

## 2. 評估面向（建議初始權重）
- 出勤與準時：25%（遲到、未依規定通報、無故缺勤；核准假別不列違規）
- 任務履約：25%（準時到站率、任務完成率、漏執行/未完成及原因）
- 作業品質：20%（漏送、錯送、短少、貨損、簽收/回報正確性）
- 安全駕駛：20%（事故、交通違規、危險駕駛及安全作業違規；須先確認事實與責任）
- 車輛管理與工作配合：10%（車況異常通報、車輛清潔、保養配合、交辦與回報時效）
權重可調整，且各項須顯示原始件數、分母、比率與資料來源，不只顯示總分。

## 3. 遲到紀錄與累積計分（建議起始值，可由管理端調整）
每次遲到建立事件：排定上班/到站時間、實際時間、遲到分鐘、班別/任務、原因、回報時間、主管確認、證據及是否核准排除。
建議計點：
- 1–5 分鐘：1 點
- 6–15 分鐘：2 點
- 16–30 分鐘：3 點
- 超過 30 分鐘：5 點
- 無故未到/未依規定通報：另列重大事件，建議 8 點並要求主管覆核
累積方式：
- 月累積、季累積、年度累積分開計算。
- 同一事件不可重複計點；修正需留原紀錄及原因。
- 可設定滾動 30/90/365 天統計，避免只看單一月份。
- 同時顯示遲到次數、總遲到分鐘、平均遲到分鐘、不同級距次數及累積點數。
- 遲到點數只作管理評估提示，不應直接自動扣薪或自動作成懲處。

## 4. 公平性與排除規則
以下情況不得直接算司機違規，須記錄原因並由主管確認：主管臨時改派/改班、派車資訊錯誤或通知過晚、前一趟作業延誤且非司機可控制、場站排隊/管制、交通事故或道路突發管制、天候或不可抗力、核准請假及其他經核准情形。
資料需區分「已確認違規」「待查證」「核准排除」「非司機因素」。不可只憑單一回報或未查證客訴扣分。

## 5. 其他評估指標
- 出勤：應出勤日、實際出勤日、核准假別、無故缺勤及未通報。
- 準時：準時任務數/應完成任務數、準時率、延誤原因分類。
- 履約：派定任務、完成任務、未完成、取消及改派原因。
- 品質：漏送、錯送、貨損、短少、簽收資料錯誤、回報不完整。
- 安全：事故/違規件數、責任判定、嚴重程度、改善及再發情形。
- 車輛：出車前檢查、異常通報、保養配合、車輛清潔及設備保管。
- 配合：臨時調度回應、作業回報時效、教育訓練完成情形。
可增加主管評語及司機自評，但主觀評語不得取代客觀事件資料。

## 6. 評分呈現
建議總分 100 分，事件扣點與指標權重需經公司確認後才正式計算。初期可先採「指標儀表板＋事件累積」試行一至兩個月，再校準權重。
建議分級（試行參考，不作自動懲處依據）：
- 90–100：表現良好
- 80–89：符合期待
- 70–79：需留意/輔導
- 70 以下：需主管面談及改善計畫
重大安全事件另行啟動調查，不應被高總分抵銷。

## 7. 改善與申覆
司機可檢視與本人相關的紀錄及評估摘要，對錯誤資料提出申覆。主管需記錄處理結果、依據及日期。改善計畫包含問題、目標、期限、輔導/訓練內容、追蹤結果及是否再發。
評估資料需限制權限，避免公開排名或不必要揭露個人資料。

## 8. 建議資料表（先檢查現有司機與任務 schema）
- driver_performance_rules：評分規則版本、權重、門檻及生效日期。
- driver_incidents：遲到、出勤、品質、安全及車輛相關事件。
- driver_score_periods：月/季/年評估摘要及各項指標。
- driver_improvement_plans：改善計畫與追蹤。
- driver_review_appeals：司機申覆及主管處理。
- driver_performance_audit_logs：評分規則及評估資料異動紀錄。
需沿用現有司機主檔及派車任務關聯，不另建重複司機名冊。

## 9. 驗收條件
- 可依司機、日期、事件類型查詢紀錄。
- 遲到自動計算分鐘、級距及月/季/年累積。
- 可設定核准排除與主管覆核，排除事件不納入違規點數。
- 評估顯示原始件數、比率、分母、點數及資料來源。
- 評分規則具版本與生效日期，修改不回算覆蓋舊期結果。
- 司機可提出申覆；主管處理全程留痕。
- 不得以系統分數自動扣薪或自動懲處；正式人事措施依公司制度及適用法令辦理。
- 不影響既有司機、車輛、派車及港口業務資料。
