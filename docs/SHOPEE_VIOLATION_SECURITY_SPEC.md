# 蝦皮違規記點、罰則與資料安全規格（第一版）

> 依使用者於 2026-10-30 提供之《運輸商作業規範管理辦法》掃描 PDF 整理。文件表格標示 2026/07/01 更新。原始 PDF 為掃描影像，部分細字辨識不可靠；本文件只定義系統結構、流程及已能辨識的分類，不把不確定的條款/金額當成正式規則。正式啟用前須由管理者逐條對照原件覆核。

## 1. 建置目標

建立可追溯的違規事件、評鑑扣分、罰款、申訴、責任歸屬與改善追蹤模組。規則必須可版本化，支援不同作業類型、車隊/自有司機、累犯條件及不同處置。

**罰款金額、評鑑扣分、內部績效點數、停線/停派/不得再錄用等處置是不同欄位與不同決策，不得混算。** 不因建立違規紀錄就自動扣款或懲處。

## 2. 來源文件分類（待逐條核對）

依來源文件可辨識的主要分類：
- 賣家上收作業規範
- WH-NDD 日常作業規範
- NDD 日常作業規範
- 門市作業規範
- 門市場域規範
- 理貨中心廠區規範（工安）
- 理貨中心廠區規範（其他）
- 雙損與貨資
- 客訴及服務態度

每一條規則需有：規則代碼、作業類別、違規項目原文、適用對象、計次單位、判定標準、罰款金額/計算方式、評鑑扣分項目、扣分權重、累犯週期/級距、其他處置、生效日、失效日、來源頁碼、覆核狀態。

## 3. 規則版本管理

- 規則版本以文件版本及生效日管理；來源文件目前標示 2026/07/01 更新。
- 新版規則以新增版本方式建立，不覆蓋舊版。
- 每筆違規建立時，固定引用當時適用的 rule_version_id 及 rule_id，日後改規則不得回頭改寫歷史案件。
- 未經雙人覆核的規則維持「草稿/待覆核」，不得自動計算正式罰款或扣分。
- OCR 無法確認的文字、金額、扣分、條件一律標示「待核對」，不自行推定。

## 4. 違規案件流程

1. 建立案件：唯一案件編號、車趟、車隊/自有司機、發生時間/地點、回報人、違規類別及初步描述。
2. 證據收集：照片、影片、GPS/到離站時間、簽收資料、LINE/Email/系統通知等；保留原始檔及上傳時間。
3. 規則比對：選擇有效版本的違規條款；系統只顯示規則建議，不自動認定責任。
4. 主管覆核：責任狀態為待確認/全責/部分責任/無責；需填判定理由及證據。
5. 罰款及扣分：分開計算及記錄蝦皮罰款、評鑑扣分、我方內部績效點數、車隊應負擔及實際扣款。
6. 申訴/溝通：記錄送件內容、對象、日期、附件、回覆及結果。
7. 結案：保留結案人、時間、原因、最後金額/扣分及完整異動歷史。

## 5. 金額、扣分與處置分離

每一違規案件可關聯多筆財務/評鑑紀錄，至少分開保存：
- 蝦皮原始開罰金額、申訴中金額、最終確認金額。
- 開罰對象（我方/合作車隊/其他）、開罰來源及通知日期。
- 我方責任判定、車隊應負擔金額、已扣款金額、未結金額。
- 評鑑扣分項目及扣分權重（來源規範原值）。
- 內部司機績效點數（需獨立制度，不可直接沿用蝦皮評鑑扣分）。
- 其他處置（停線、停派、司機替換/不得再錄用等），需主管核准並記錄依據。

金額及扣分欄位不可互相推導。部分來源條款出現「當月第一次/第二次/第三次」遞增罰款，須以可設定的累犯規則實作；累犯統計範圍、重置週期、是否按司機/車隊/違規代碼計算，必須依原文及管理者覆核設定，不能自行假設。

## 6. 資料表建議

- `violation_rule_versions`: 規範版本、生效日、來源文件資訊、覆核狀態。
- `violation_rules`: 條款主檔、分類、原文、適用對象、來源頁碼。
- `violation_rule_penalties`: 罰款、計次單位、累犯級距、扣分項目/權重、其他處置。
- `violation_cases`: 個別違規案件及責任狀態。
- `violation_case_evidence`: 私有附件 metadata、檔案雜湊、上傳者及關聯案件。
- `violation_case_reviews`: 主管覆核與申覆決定。
- `violation_fines`: 多筆開罰及扣款明細，支援蝦皮向我方/車隊開罰兩種模式。
- `violation_appeals`: 申訴往返與結果。
- `violation_case_events`: 不可覆寫的案件時間軸。
- `violation_audit_logs`: 敏感操作稽核紀錄。
- 規則與案件需關聯車趟、車隊及司機；歷史資料不得因司機/車隊停用而刪除。

## 7. 資料安全與防外洩要求（上線阻擋條件）

### 身分驗證
- 所有管理頁面與 API 預設拒絕未登入請求。
- 管理員/主管帳號啟用 MFA；高風險操作再次驗證。
- 使用安全、HttpOnly、Secure、SameSite Cookie；避免將長效 token 存於 localStorage。
- 登入失敗限速、短期鎖定及異常登入告警；密碼使用成熟的 Argon2id 或 bcrypt 雜湊，不可明文保存。

### 權限隔離
- 採 RBAC 最小權限：系統管理員、主管/覆核者、調派人員、財務、合作車隊窗口、自有司機。
- 合作車隊帳號只能存取被授權車隊自己的派車、案件及回報；不可透過更改 URL/API ID 讀取其他車隊資料。
- 司機僅能讀取本人被授權的車趟及本人案件，不得查看他人績效或罰款。
- 罰款金額、內部責任判定、員工個資及內部備註需額外欄位級權限；車隊外部帳號不得看到我方內部備註及其他車隊資料。
- 每支 API 都在伺服器端驗證身分、角色、資源歸屬；不可只靠前端隱藏按鈕。

### 傳輸、儲存與秘密管理
- 全站 HTTPS；資料庫使用受控連線及靜態加密（由託管資料庫/磁碟加密提供，必要時對敏感欄位做應用層加密）。
- 附件放私有儲存空間，不使用公開 bucket 或永久公開連結；下載採短效、限權簽名 URL。
- 上傳限制檔案類型/大小，檢查 MIME 與副檔名、惡意檔案掃描；禁止執行上傳檔案。
- API Key、DB 密碼、LINE Token、Google 憑證只能存部署平台 Secret/環境變數或 Secret Manager；不得提交 Git、前端 bundle、日誌或錯誤訊息。
- GitHub repo 不放原始含公司印章/簽署資訊的 PDF、個資、真實案件附件或正式資料庫備份。

### 稽核、備份與事件應變
- 對登入、匯出、檢視敏感資料、權限變更、規則修改、責任覆核、罰款/扣分調整、附件下載及刪除嘗試建立稽核紀錄。
- 稽核紀錄包含操作者、時間、動作、目標、結果及必要的前後值；不得記錄密碼、Token 或附件內容。
- 違規案件、罰款及績效紀錄採軟刪除/停用，禁止一般使用者永久刪除；更正採新增異動，不覆蓋原紀錄。
- 定期加密備份資料庫與附件，備份權限獨立於一般應用程式帳號；定期執行還原演練。
- 建立疑似外洩應變程序：停用受影響帳號/Token、撤銷工作階段、保存稽核證據、評估受影響資料、通知責任人並依適用法規處理。

### 開發及部署安全
- 新功能先在 staging/test DB 開發，不連正式資料庫。
- CI 加入依賴漏洞掃描、Secret scanning、靜態分析及測試；禁止將真實資料放入測試 fixture。
- 生產環境錯誤訊息不得暴露 stack trace、SQL、環境變數或內部路徑。
- CORS、CSRF、SQL injection、XSS、IDOR、檔案上傳及速率限制納入安全測試。
- 上線前完成權限矩陣測試、跨車隊存取測試、附件直連測試、備份還原測試及安全檢查。

## 9. 第一階段建議

先建立規範版本/條款主檔、違規案件、證據附件 metadata、覆核流程及不可覆寫的稽核軌跡；先用待核對條款測試，不啟用自動罰款。待條款逐條確認後，再開啟自動計算、累犯級距及報表。
