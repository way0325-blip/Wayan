# 車隊聊天室與調度工作區

左側列出本平台車隊及群組驗證狀態；中間以對話泡泡呈現實際收到的群組文字與 Bot 回覆，顯示處理及回覆送達狀態；右側列出所選車隊最近任務、異常案件，以及指定台灣作業日期的門店車趟報到統計。右側案件按鈕沿用既有異常明細與處理流程。

沿用受登入及 admin／dispatcher 後端授權的 API：GET /api/fleet-ops/activity-status、/activity、/tasks、/incidents，及 GET /api/store-delivery/trips?date=。無新增 API、資料表、migration、環境變數。前端不直接操作資料庫，沒有新增任意訊息發送端點。

報到數讀取 delivery_trips.required_checkins 與既有 API 的 checked_in。每車趟缺額分別取非負值後加總；已取消車趟不計入。報到統計最多載入500趟；任務及案件各顯示最近5筆，其餘仍在原有管理清單。任務清單跨日期，日期欄只篩選門店車趟報到。

新訊息透過既有 wayan:refresh 通知更新，也每30秒檢查目前開啟頁面。快速切換車隊時，以請求世代丟棄較晚返回的舊車隊結果，避免對話與任務混入。已收回訊息不顯示原文及原 Bot 回覆。所有文字以 HTML escape 輸出。

桌面呈現三欄，較窄螢幕將調度區移至下方，手機上下排列。圖片、語音、貼圖只保留現有事件類型提示；尚無附件預覽或人工發訊。人工回覆仍在LINE操作。

本機與雲端仍使用獨立資料庫，現有提示與雲端連結保留。雲端目前仍是舊畫面，需將此測試分支部署至獨立測試服務後才能使用新版。不得部署正式環境或合併PR。

scripts/verify-fleet-chat.mjs 提供可重用的 DOM 驗收函式，由驗收工具注入 JSDOM。它只允許 http://127.0.0.1:3081，並要求 disposable staging fixtures，驗證純文字防注入、Bot 回覆、任務及案件真實 API、30需求／1報到／29缺額、車隊快速切換、收回事件與異常處理視窗。不得用於有業務資料的本機3080或雲端環境。
