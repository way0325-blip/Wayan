# 蝦皮營運整合與本機驗收

分支：`staging/shopee-task-checkin-20261101`；基礎：`staging/store-delivery-trips-20261101`。僅供本機／獨立 staging，禁止部署或合併正式環境。

## 作業流程

1. 「蝦皮店到店」登錄或 CSV 匯入門店訂單，選擇大園、楊梅、觀音取貨倉。
2. 同日同倉的多筆訂單可跨行政區合併車趟，輸入自訂編號、名稱及需求報到人數，選擇合作車隊。
3. 明細可複製完整 LINE 任務文字；已綁定群組可排入 LINE 通知。傳送狀態與失敗重試沿用既有通知佇列。
4. 司機在對應車隊群組輸入 `車趟報到 SH-001`。需求30時首人成功後為已報到1、尚缺29。相同帳號同一車趟僅計一次，不以訊息數計算；重送不重複扣除。僅開放今日尚未結束的車趟。
5. `車趟狀態 SH-001` 查詢路線及報到進度；平台透過既有 SSE 更新。報到數變化後可再次按通知，未變更的同版本同報到數不重複排送。
6. `車趟異常 SH-001 延誤 說明內容` 建立案件。類型：延誤、車輛異常、貨損、事故、其他。沿用異常處理狀態、歷程及 Sheets 同步佇列。
7. 「罰款規則管理」人工立案時可選關聯異常。僅可使用已核實、已生效規則；相同異常與規則不得重複立案。金額、點數不自動填入，主管覆核後才確認。Sheets 罰款案件責任欄包含異常編號。

## 資料與 API

增量 migration `006_delivery_checkins.sql`：車趟增加唯一 `task_code`、`task_name`、`required_checkins`；新增 `delivery_checkins`，車趟與回報者雜湊唯一、事件編號唯一。保留既有自動 D 編號與歷史資料。

異常增加 `delivery_trip_id`，原任務欄允許空值，資料庫要求原任務／門店車趟恰有一種。罰款增加 `incident_id` 及案件／規則唯一索引。既有 Sheets 工作表與欄位不刪除、不覆寫；沿用「異常案件」「異常處理歷程」「罰款記點案件」「罰款處理歷程」。

- `POST /api/store-delivery/trips` 增加 `taskCode`（英數、底線、連字號，1–40字，轉大寫）、`taskName`（1–100字）、`requiredCheckins`（1–10000）。舊 API 呼叫可省略，預設需求1與自動編號。
- `GET /api/store-delivery/trips` 增加報到計數與上述欄位。
- `GET /api/store-delivery/trips/:id/line-text` 回傳完整任務文字，需調度／管理員登入。
- 簽章驗證後的既有 LINE webhook 新增上述三個群組指令；只可操作綁定車隊的車趟。
- `POST /api/penalty-cases` 增加選填 `incidentId`，驗證車隊歸屬及重複立案。

報到採車趟資料列鎖與交易，與稽核共同提交；LINE inbox 保留事件去重。通知長度上限4200字，路線過長會提示至平台查完整內容，報到與異常指令保留在通知內。剪貼簿受瀏覽器限制時，可手動選取文字複製。

## 驗收及限制

自動測試只使用獨立 `wayan-staging-db` 測試叢集，不清除使用者本機營運資料；測試帳號、頻道與地址均為合成資料。外部推播使用 mock，不會傳給真實群組。測試結果見交付文件。

需求報到人數是此路線任務的報到目標，不代表已建立30筆實際派車或預留30台車；原車趟仍保留一組司機／車輛的派遣流程。既有「車隊每日累計車數」保留獨立口徑，與個人報到不相加。

已綁定群組成員均可報到；這不是獨立的司機身分審核，尚未限制單一帳號同時報到不同車趟。訊息收回不會取消已成立報到或案件。異常不是自動判罰，PDF草稿仍須人工核實條件與生效日。

LINE Channel Secret／Token、可公開接收測試 webhook 的 HTTPS 與群組綁定尚待驗證。既有 Render 網址未查詢或變更。Node 無人值守 Google 服務帳號憑證尚未設定，連接 Drive 並不等於背景程式有寫入權限；缺設定的工作標記 blocked，可於設定後重試。尚未完成真實 LINE → Sheets、實體手機與桌面人工驗收。

本機啟動器版本更新為 `shopee-checkin-v8`，需由使用者重新執行啟動器以載入新後端。程式碼檢查通過不代表目前3080舊程序已重啟。
