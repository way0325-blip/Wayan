# LINE 車隊動態與關鍵字回覆

本機測試版本，不部署正式環境。接續前一測試分支，不修改 main。

## 畫面

「夥伴車隊營運」新增各車隊 LINE 動態及管理員關鍵字設定。所有車隊都列出，尚未綁定、無事件、停用等狀態如實顯示；不以「Bot 已加入」推定 Webhook 已接通。

動態以收件當時的綁定車隊保存，不會隨群組改綁而將舊訊息轉至新車隊。可依車隊篩選，每頁50筆並載入較早紀錄；使用資料庫完整微秒時間及事件ID分頁。文字、處理狀態、Bot回覆可檢視。圖片、影片、語音、檔案、貼圖與位置目前僅顯示類型；沒有下載附件或取得LINE顯示名稱。成員以群組範圍的雜湊代號顯示。

使用既有登入SSE觸發更新，並每30秒補查。接收時間是平台收件時間，非GPS或實際到場時間；連線及排程可能造成延遲。

## 關鍵字

預設6組：說明、指令、報到、異常、事故、聯絡調度。僅啟用且已綁定車隊的群組可使用。管理員可新增、修改、停用；完整字串比對（去除使用者訊息前後空白），不作模糊辨識。

回覆內容適用全部已綁定車隊，不可填入單一車隊私人資料。每組最多1500字，最多100組。內建任務、承接、拒絕、到站、完成與蝦皮指令不能被自訂文字覆蓋。輸入「報到」「異常」只顯示說明，不建立營運紀錄。實際報到須使用「蝦皮報到 總數」，一般車隊異常仍須T任務編號。蝦皮S任務異常由調度人工登記，尚無獨立S任務異常指令。

這些設定是平台Webhook回覆，沒有變更LINE官方帳號管理後台的自動回覆。實際頻道若另啟用官方後台自動回覆，可能收到兩套訊息，驗收時須核對設定。原有一般群組未知指令仍沿用指令說明回覆。

## API 與 migration

| 方法 | 路徑 | 權限／用途 |
|---|---|---|
| GET | /api/fleet-ops/keywords | admin，關鍵字清單 |
| PUT | /api/fleet-ops/keywords | admin，新增／更新／停用；同交易稽核 |
| GET | /api/fleet-ops/activity-status | admin／dispatcher，所有車隊接收狀態 |
| GET | /api/fleet-ops/activity?fleetId=&before= | admin／dispatcher，動態與分頁 |

migration004新增line_keyword_replies、fleet_line_activity、line_unsent_messages；無刪表、刪欄位或刪除既有營運資料。群組事件在共用調度鎖內處理，投影與業務事件同交易提交，沿用簽章與事件去重。動態API不返回Webhook原始payload、replyToken、LINE user ID或金鑰。

群組綁定碼不進入動態牆。收到收回訊息事件時，隱藏對應動態並清除Webhook收件箱原文與回覆文字；先收到收回再收到原文時也不展示。已建立的營運報到／案件仍保留稽核，不能以收回聊天自動撤銷營運行為。尚未實作LINE訊息編輯事件的完整內容更新，也沒有回補既往聊天或上線前事件投影。

## 連線與其他外部來源

動態投影與業務事件同交易保存；若業務處理整筆交易失敗，該事件尚不會出現在動態牆，需由管理端事件紀錄檢查並重試。不能將動態牆視為完整的LINE聊天備份。未設定自動刪除期限，需另行制定訊息保留政策。

每個車隊需對應真實群組；Bot須加入群組，測試HTTPS Webhook須可從LINE到達，頻道金鑰需在本機測試設定中提供。localhost不能直接被LINE呼叫。提供過的Render URL尚未確認隔離狀態，本次未使用。

控制台未來可再接其他系統的Webhook、授權API定時查詢或檔案匯入；必須先取得實際介面文件、資料格式與授權。GPS／車機與其他物流API本次未連接，也沒有假設廠商一定提供API。Google Sheets背景同步仍需獨立測試授權。

官方依據：[LINE群組事件](https://developers.line.biz/en/docs/messaging-api/group-chats/)、[Webhook接收及收回訊息](https://developers.line.biz/en/docs/messaging-api/receiving-messages/)。
