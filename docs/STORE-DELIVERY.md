# 蝦皮店到店：三倉、分區門店訂單與多訂單車趟

僅本機與獨立staging。沿用Node.js、Express、PostgreSQL與既有登入／授權。沒有將港口貨櫃資料改成虛構的門店資料。

## 操作流程

1. 「訂單與車趟」入口改為「蝦皮店到店」。頁面預設門店配送，原港口畫面與資料保留於「既有港口紀錄」，原API也保留。
2. 取貨倉固定為大園倉、楊梅倉、觀音倉。正式地址由管理員維護；未提供就顯示待提供，不猜座標。本機使用者提供的倉庫地址由私人配套設定載入，不納入公開專案。
3. 配送範圍為基隆市、臺北市、新北市、桃園市、新竹市、新竹縣，共77個行政區選項；不含宜蘭。行政區選項不表示蝦皮在每區都有營業門店。
4. 管理員登錄或CSV匯入門店代碼、名稱、縣市、行政區、完整地址、來源及核對狀態。只有已核對且啟用門店能建立訂單。沒有預填假門店，也沒有聲稱官方門店清單已自動同步。
5. 新增或CSV匯入配送訂單，每筆含唯一訂單編號、取貨倉、門店、日期、件數與備註。批次全部成功或全部回滾，拒絕重複編號。
6. 依日期、取貨倉及行政區檢視訂單；跨區切換仍保留勾選。選多筆訂單後建立一趟車：同一日期、同一取貨倉，可跨縣市及行政區，最多200筆。
7. 每筆訂單保留一個停靠項目；同門店多張訂單不合併明細。待派車時可上下調整完整停靠順序；不自動宣稱最短路線、ETA或貨車可通行路線。
8. 合作車隊可先不指定。若要沿用「蝦皮任務派單」的需求確認及LINE總車數報到，選擇同日、同車隊的已確認需求。連結車趟不可超過該需求確認數，且不重複計入承接容量；獨立車趟則另計容量。
9. 指派司機與車輛時檢查可用狀態、證照／保養／驗車期限及請假。資源在一趟未完成任務中就不接受另一趟派車，亦檢查既有港口任務。這是保守的未完成任務鎖定，不是含預估回場時間的未來時段預約系統。
10. 出發後逐筆登記送達，全部送達才能完成車趟並釋放資源。取消僅限未出發車趟，需原因，訂單回待安排，舊停靠與車趟紀錄保留。
11. 車趟及停靠站保存當時的取貨地址、門店名稱、行政區與地址快照；後續修改名冊不改動舊車趟。可匯出完整車趟CSV；公式開頭文字作為純文字輸出。

## 地圖與資料來源

- [蝦皮官方門市查詢入口](https://shopee.tw/m/spxservicepoint)連到[SPX服務門市地圖](https://spx.tw/service-point)。官方地圖需JavaScript；沒有查得可依賴的公開門店批次同步API，因此本次未建立未經證實的抓取介面。
- 分區與門店地址提供[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)查詢及逐段駕車路線連結，不需Google API金鑰。只在使用者點選時開啟查詢；未使用付費Places／Directions API。
- 使用者可載入[OpenStreetMap參考底圖](https://wiki.openstreetmap.org/wiki/Export)，由官方iframe呈現及保留其歸屬標示。底圖為北臺灣區域參考，不是自動標註的官方門店／倉庫座標；外部服務可用性及實際地圖畫面待瀏覽器驗收。
- 行政區資料參考[政府開放資料目錄](https://data.gov.tw/dataset/7441)。下載圖資端點回403，本次未繞過限制或取得其幾何邊界；平台使用行政區名稱選單，不宣稱繪製官方行政區界線。

## CSV

門店欄位：`門店代碼,門店名稱,縣市,行政區,地址,來源`。匯入介面另有整批已核對勾選框；未勾選會登記為待核對門店。

訂單欄位：`訂單編號,取貨倉,門店代碼,作業日期,件數,備註`。日期YYYY-MM-DD，取貨倉可填倉名或DAYUAN／YANGMEI／GUANYIN。Excel需另存UTF-8 CSV；本次未加入原生XLSX解析。每批1～500筆，專用API本文上限2MB，不擴大其他API的100KB限制。

件數不是重量或體積，未自動推算車輛載重或容積。門店來源、地址與當日營業情況需由營運核對。

## API、交易與資料庫

所有/api/store-delivery API限登入admin／dispatcher。門店匯入、門店更新及倉庫地址維護限admin。所有寫入由既有交易路由包裝器保存與稽核，錯誤回應會回滾。共用調度鎖870033，資源派遣另共用870032，與既有派車防衝突。

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | /config | 三倉、行政區與官方地圖入口 |
| PATCH | /warehouses/:id | 倉庫地址（admin） |
| GET | /stores | 門店名冊與區域查詢 |
| POST | /stores/import | 原子門店批次登錄／依代碼更新（admin） |
| GET | /orders?date= | 門店訂單 |
| POST | /orders/import | 原子批次訂單匯入 |
| POST | /orders/:id/cancel | 取消未安排訂單 |
| GET/POST | /trips | 日期車趟／多訂單合併（UUID冪等） |
| GET | /trips/:id/stops | 快照停靠明細 |
| PUT | /trips/:id/sequence | 調整完整停靠順序 |
| POST | /trips/:id/dispatch | 指派司機車輛 |
| POST | /trips/:id/start | 開始配送 |
| POST | /trips/:id/stops/:stopId/deliver | 逐筆送達（重送不重複異動） |
| POST | /trips/:id/complete | 全部送達後完成 |
| POST | /trips/:id/cancel | 取消未出發車趟並釋放訂單 |
| POST | /trips/:id/notify | 車趟排入既有LINE outbox |

增量migration005新增delivery_warehouses、delivery_stores、delivery_orders、delivery_trips、delivery_trip_stops五表。透過部分唯一索引限制每筆訂單只能屬於一個未釋放車趟；完整順序更新使用延後檢查的唯一約束。需求連結使用既有shopee_assignments外鍵。已連結需求不得刪除、重設或縮減到已安排數以下；有歷程的車隊／司機／車輛保留資料。沒有刪除既有資料表或欄位。

LINE通知沿用既有群組綁定、版本防過期與固定重試鍵。群組可輸入「門店車趟」查看本車隊未結束D編號車趟；不混用T任務或S需求編號。新門店車趟的出發／送達／完成仍由調度在平台登記，尚無D車趟司機私人回報指令。獨立未連結需求的D車趟不會自動增加原S需求的總車數報到上限。

## 本階段限制

單次清單上限：門店1000、當日訂單1000、車趟500。達上限畫面會提示，統計為已載入清單；門店按縣市與行政區向後端查詢，大量資料需分區／分日。尚未建立無上限全量查詢或大型資料分頁管理。

官方門店批次同步、倉庫經緯度、門店座標標記、全程路線最佳化、交通／ETA／貨車限制、重量與容積檢查、原生XLSX匯入、D車趟私人LINE完成回報、門店訂單與車趟新增Sheets專表均未實作。原港口儀表板仍統計原港口資料，門店配送數字在本頁單獨顯示。實際LINE連線、外部地圖及手機／桌面畫面需後續驗收，不以模擬測試取代。
