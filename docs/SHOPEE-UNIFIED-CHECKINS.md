# 單一蝦皮工作區與三倉中文報到

側邊欄僅保留「蝦皮店到店」入口，內含「訂單與車趟／報到」及「路線需求／任務派單」。舊派單導覽保留為程式相容入口，但不再重複顯示；舊功能與資料均保留，共用作業日期同步deliveryDate、shopeeDate及opsDate。原港口歷史入口不變。

新增009增量migration建立delivery_checkin_aliases：trip_id連結原車趟，service_date及alias當日唯一，batch_key作本批統計。原task_code、訂單、報到事件不改名刪除；代號變更保留稽核及精確版本，已出發或報到者不可變更。跨日可重用同一中文代號。原ASCII車趟碼仍有效。

POST /api/store-delivery/checkin-aliases 沿用登入與admin／dispatcher授權、既有路線鎖與交易，整批1～200筆驗證、重複檢查、版本檢核及回滾。畫面可勾選車趟後按「產生中文報到代號」，每取貨倉設定前綴與起始號，僅設定代號，不更改取貨倉。

LINE群組須先綁定且車趟指派該車隊。支援「車趟報到 楊梅1」、「車趟報到楊梅1」、「報到 楊梅1」及直接「楊梅1」。直接輸入已登記代號即視為報到；其他聊天不會自行變成報到。相同帳號對同一車趟重送不重複，車趟名額滿不再增加。群組不能使用他隊代號。回覆列出本車趟數量及同批、同日、同車隊的合計報到；需求30、報到1時剩29。查詢「車趟狀態 楊梅1」，舊完整車趟碼仍支援。中文代號優先處理，避免在異常填報尚未取消時誤寫成異常描述。

新模擬批次預設楊梅、大園、觀音各10車、每車2筆訂單。選填STAGING_CHECKIN_SETUP_DATE、STAGING_CHECKIN_SETUP_REQUEST_ID、STAGING_CHECKIN_SETUP_FLEET_NAME只在通過既有安全檢查的staging啟用：辨識既有當日30個尚未使用模擬車趟，若為舊楊梅20／觀音10布局，依使用者授權調整其中10個模擬車趟至大園、保留訂單與原編號並稽核；再指派到唯一且已驗證綁定的指定車隊，建立三倉各10個中文代號。若有分派、司機、報到或狀態不符則停止，不覆寫業務資料；日容量及路線承接上限仍檢查。可用於既有安樺車隊測試群組。完成後清空暫時設定；重啟不重建。

模擬車趟仍固定標記is_simulated，禁止LINE主動通知及營運Sheets寫入；模擬車趟異常指令亦阻擋寫入營運表單。LINE報到回覆會標示模擬。此次不代表正式啟用、不更改Webhook或Secrets、不新增付費資源。

測試包含舊模擬布局安全轉換、三倉30個代號、30→29、全形數字、重送／並行防超量、原代碼相容、跨車隊隔離、代號改名限制、異常填報優先順序、簽章Webhook與事件去重；DOM驗收涵蓋中文編號表單、複製LINE文字與單一入口／共用日期。舊全日期需求勾選仍保留為路線清單查詢選項。

由門店車趟管理的車隊，其任務派單報到數直接讀取delivery_checkins，不再另用累計填報計數；舊型車隊任務保留原累計總數流程，避免混算。
